# デジタルアーツ ― AIを使った総点検で、クラウドサービスの運用環境と社内環境に2025年7月頃からの不正アクセスの痕跡、i-FILTER@Cloudなど6サービスの一部顧客情報が閲覧された可能性

## 要点

### 発表された事実

- デジタルアーツは2026年10月21日、昨今のサイバー攻撃の増加を受けて10月9日にAIを活用した自社のシステム・製品・社内環境の総点検を行い、従来の点検では見つからなかった、クラウドサービスの運用環境と社内環境への不正アクセスの痕跡を発見したと公表した。痕跡には2025年7月頃にさかのぼるものが含まれる（[デジタルアーツ](https://www.daj.jp/webtopics/1354/)、[適時開示](https://www.daj.jp/ir/data/daj2326_202703_3q_1.pdf)）。
- クラウドサービスの運用に使う認証情報が第三者に不正に取得され、それを使ってサービス運用環境に侵入されたことが判明した。これにより、i-FILTER@Cloud、m-FILTER@Cloud（Modern Edition）、m-FILTER MailAdviser Microsoft 365 対応版、FINAL CODE@Cloud、z-FILTER、Desk を使う一部の顧客の情報が閲覧された可能性がある（同）。
- 10月21日正午時点で、顧客情報の外部への持ち出しは確認されておらず、悪用や二次被害の報告もない。新たな不正アクセスも確認されていない（同）。
- 同社は対象6サービスのすべての利用者に、管理者用と利用者用のパスワードの変更を求めている。顧客の環境に導入するソフトウェア版は対象外（同）。

### わかっていないこと

- 運用用の認証情報がどこから、どうやって盗まれたのか
- 2025年7月頃から点検までの約1年3か月の間に、攻撃者が何をしていたのか（継続的な侵入か、断続的か）
- 「閲覧された可能性」のある顧客情報の項目と件数、対象顧客の数
- 停止したという「不審なプログラム」が何で、どこで動いていたのか
- 社内環境への侵入で何が見られたか、製品の開発・配布環境に影響はなかったのか
- 「追加の対応が必要な一部のお客様」とはどんな条件の顧客か
- 業績への影響

### 関係しそうな既知の手口

- （考察）運用者の認証情報を奪ってサービスの裏側に入る形は、10月に相次いだ楽天ドライブの管理用アカウントやユミルリンク「Cuenote FC」のサポート担当者の認証情報の事例と同じ型だ。違うのは、痕跡が1年以上前までさかのぼる点で、今回の「侵入の波」の前から入られていた可能性がある。

## 概要

- 情報セキュリティ製品のベンダーが、自社クラウドサービスの運用環境と社内環境への不正アクセスを公表した。
- 運用用の認証情報が盗まれ、i-FILTER@Cloudなど6サービスの一部顧客情報が閲覧された可能性がある。持ち出しは確認されていない。
- 痕跡は2025年7月頃までさかのぼり、見つけたのは10月9日のAIを使った総点検だった。

> この記事では、公式発表・報道で確認できた内容を「事実」、筆者の推測や意見を「考察」として分けて書いています。確認できなかった情報は書いていません。

## 発表内容の整理

**事実（デジタルアーツの発表）**

| 項目 | 内容 |
| --- | --- |
| 発見のきっかけ | 10月9日、AIを活用した総点検。従来の点検では発見に至らなかった |
| 侵入された範囲 | クラウドサービスの運用環境と社内環境 |
| 侵入の方法 | クラウドサービスの運用に使う認証情報を第三者が不正に取得し、それを使って運用環境に侵入 |
| 最も古い痕跡 | 2025年7月頃 |
| 影響の可能性 | 対象サービスを使う一部顧客の情報が第三者に閲覧された可能性 |
| 対象サービス | i-FILTER@Cloud、m-FILTER@Cloud（Modern Edition）、m-FILTER MailAdviser Microsoft 365 対応版、FINAL CODE@Cloud、z-FILTER、Desk |
| 対象外 | 顧客の環境に導入するソフトウェア版 |
| 持ち出し・悪用 | 10月21日正午時点で、持ち出し・悪用・二次被害は確認されていない |
| 利用者へのお願い | 対象サービスの管理者用・利用者用パスワードの変更。追加対応が必要な顧客には個別に連絡 |
| 同社の対応 | 認証情報の無効化と交換、不審なプログラムの停止、サーバー認証鍵の交換、監視の継続、サービスとネットワークの再構築 |
| 問い合わせ | お客様専用サポート窓口 k-support@daj.co.jp |

**考察**

この発表でいちばん重いのは、侵入の痕跡が2025年7月頃まで戻ることだ。ここ1か月で国内の公表が急増した不正アクセスの多くは、9月から10月にかけての短い期間の侵入として説明されている。デジタルアーツの件は、少なくとも痕跡の上ではそれより1年以上前から始まっていたことになり、同じ波の一部なのか、別の長期の侵入なのかは、この発表だけでは判断できない（考察）。

対象になったi-FILTER@Cloudやm-FILTER@Cloudは、利用組織のWebアクセスやメールの通り道に置かれるサービスだ。運用環境に入られた場合、気になるのは顧客の登録情報だけでなく、フィルタリングの設定やログ、メールの中身にまで手が届いたかどうかだ。発表は「一部のお客様の情報が閲覧された可能性」とだけ書き、項目を示していない。利用組織にとってはここがわからないと影響を評価しにくい（考察）。

痕跡を見つけたのが「AIを活用した総点検」で、それまでの点検では見落としていたと会社自身が書いている点も注目に値する。正規の認証情報で入られると、ふだんのログでは正規の運用作業と見分けにくい。何が見落としの原因で、AIで何が見えるようになったのかが今後説明されれば、同じ立場の事業者にとって参考になる（考察）。

## 関係しそうな既知の手口

**事実（既知の知見・同種事例）**

- 楽天ドライブでは管理用アカウントの認証情報が奪われ、1万5382アカウント分の保存データが取得・閲覧された（当サイトの[楽天ドライブの記事](/security-notes/notes/2026-10-08-rakuten-drive-admin-credential-stored-files-15k-accounts/)）。
- ユミルリンク「Cuenote FC」では、配信基盤の脆弱性からサポート担当者の認証情報が窃取され、専用ASPプランの複数システムから情報が持ち出された（当サイトの[Cuenote FCの記事](/security-notes/notes/2026-10-20-ymirlink-cuenote-fc-support-credentials-9m/)）。
- JPCERT/CCは10月の注意喚起で、相次ぐ国内の不正アクセスについて点検を呼びかけている（当サイトの[注意喚起のまとめ](/security-notes/notes/2026-10-11-jpcert-nco-ipa-alerts-domestic-breach-wave/)）。

**考察**

運用者の認証情報は、サービス全体に届く「合鍵」だ。今回の発表では盗まれた経路が書かれていないが、社内環境にも痕跡があったことから、社内の端末や社内システムを足場にして運用用の認証情報にたどり着いた可能性は考えられる（考察。発表では確認されていない）。

## 利用者・運用者がいまできること

- 対象6サービスを使っている組織は、会社の依頼どおり管理者用と利用者用のパスワードを変更する。同じパスワードを他で使っていれば、そちらも変える。
- 管理画面の操作ログや設定変更の履歴を、2025年7月以降の範囲で見直し、身に覚えのない変更がないか確認する。
- デジタルアーツからの個別連絡がメールで届いた場合は、リンクを踏む前に公式サイトの案内や既存の窓口で本物か確かめる（本件に便乗した偽の連絡に注意）。
- 運用者の立場では、運用用の認証情報の保管場所と使える範囲、多要素認証の有無を棚卸しし、長期間使われていない、あるいは想定外の場所から使われている認証情報がないかをログで確かめる。
