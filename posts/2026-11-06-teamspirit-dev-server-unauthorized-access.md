# チームスピリット ― 開発用サーバーへの不正アクセスで情報が流出

## 要点

### 発表された事実

- チームスピリットは、利用するソフトウェア開発用サーバーの一部が第三者による不正アクセスを受け、個人情報等が外部に流出したと発表した（[チームスピリット](https://corp.teamspirit.com/news/information/2026/11/2026_1106_01/)）。
- 2026年10月27日、第三者が開発用サーバーに不正ログインし、サーバーに保管されていた認証情報を用いて、同社が利用するクラウド環境からデータを取得した。同日中に当該サーバーを停止し、外部からの接続経路を遮断した（同）。
- 流出した個人情報は、確認できた範囲で重複を除き28,824件。要配慮個人情報35件が含まれる（同）。
- 原因は未知の脆弱性ではなく、開発用に運用していたサーバーにおける設定と情報管理の不備が重なったこと。手法の詳細は模倣攻撃防止の観点から公表しないとしている（同）。
- 顧客がTeamSpirit上で運用する勤怠・工数等のデータへの不正アクセスは、発表時点では確認されていない。流出した勤怠記録は、本番環境とは別に、サービス提供・維持のために同社管理下で保管していたものである（同）。

### わかっていないこと

- 不正ログインの具体的な手法（設定不備の内容を含む）。
- 流出項目の対象者ごとの内訳の全体像（個別連絡で知らせるとしている）。
- 再発防止策の具体内容（調査結果を踏まえて改めて公表するとしている）。

### 関係しそうな既知の手口

- （考察）開発用サーバーにクラウドへ通じる認証情報と、本番相当のデータが置かれていると、開発環境の侵害が本番データの持ち出しにつながる。同社自身が、設定と情報管理の不備が重なったと説明している。

## 概要

- 対象は、TeamSpiritの現契約または過去の契約企業の担当者・利用ユーザー、資料請求や問い合わせ・セミナー申込をした人、同社の従業員（退職者を含む）である（[チームスピリット](https://corp.teamspirit.com/news/information/2026/11/2026_1106_01/)）。
- 流出が疑われる認証情報の無効化はおおむね完了し、個人情報保護委員会への報告は2026年10月30日付で完了している。対象者への個別連絡は11月6日から順次行う（同）。
- 発表時点で、流出情報の不正利用や、外部サイト・SNS等での公開は確認されていない（同）。
- 外部のセキュリティ専門機関と弁護士と連携して調査している（同）。

> この記事では、公式発表・報道で確認できた内容を「事実」、筆者の推測や意見を「考察」として分けて書いています。確認できなかった情報は書いていません。

## 発表内容の整理

**事実（チームスピリットの発表による）**

| 区分 | 流出したとされる情報（対象者によって異なる） |
| --- | --- |
| 契約企業（現契約・過去契約）の一部 | 担当者・利用ユーザーの氏名、メールアドレス、ログインID、同社が管理する識別番号・アカウント情報。問い合わせ・依頼記録の一部。サービス提供・維持のために保有していた従業員の勤怠記録の一部。契約や利用環境に関する企業情報の一部 |
| 資料請求・問い合わせ・セミナー申込者の一部 | 同社が管理する識別番号、企業に関する情報（会社名等） |
| 従業員・退職者 | 氏名、社員番号、業務用メールアドレス、入社日・退職日、誕生日（月・日）、社内システムのユーザー名・ID・アカウント情報、業務管理システムの記録 |
| 件数 | 重複除き28,824件。このうち要配慮個人情報35件 |

出典：[チームスピリット「不正アクセスによる情報漏えいに関するお詫びとお知らせ」（2026-11-06）](https://corp.teamspirit.com/news/information/2026/11/2026_1106_01/)

**考察**

- 「本番の勤怠データは無事」と「勤怠記録の一部は流出した」は両立する、と発表は説明している。後者は顧客テナントではなく、同社がサービス維持のために別保管していた分である。利用企業は、自社が入力したデータ以外に、ベンダー側の管理環境へ何が複製されているかを確認する材料になる。
- 要配慮個人情報35件の中身は公表されていない。対象者には個別連絡するとしている。

## 関係しそうな既知の手口

**事実**

- 同社は、未知の脆弱性ではなく、開発用サーバーの設定と情報管理の不備が重なったと説明した。不正アクセスの手法等の詳細は公表しないとしている（[チームスピリット](https://corp.teamspirit.com/news/information/2026/11/2026_1106_01/)）。
- 開発用サーバーに保管されていた認証情報を使い、クラウド環境からデータが取得された（同）。

**考察**

- 開発・検証環境に、クラウドの鍵や本番に近い個人データが残るのは、設定不備の典型的な組み合わせである。どの設定が誤っていたか（公開面、認証の弱さ、権限の広さなど）は分からない。

## 利用者・運用者がいまできること

- 契約企業・問い合わせ者・従業員：同社や従業員を装う不審なメール、電話、SMSに注意する。URLや添付を開かず、ID・パスワードを入力しない。同社はメールや電話で認証情報を尋ねないとしている。
- 利用企業：自社がベンダー側に渡している担当者情報や、サポート目的で提供した勤怠サンプルの有無を確認する。
- 開発環境の運用者：開発用サーバーにクラウド認証情報や本番相当の個人データを置かない。置く場合は本番と同等のアクセス制御と監視を付ける。
