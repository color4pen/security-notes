# paiza ― 検証環境が固定パスワードのまま外部から接続できる状態だった

## 要点

### 発表された事実

- paizaは2026年11月13日、開発用ステージング環境（動作検証環境）のアクセス管理の不備により、従前アクセス権限を持っていた退職者等の第三者から外部経由でアクセスされ得る状態だったと発表した（[paiza 11月13日発表](https://www.paiza.co.jp/news/20261113/access-management-notice/)）。
- 環境には本番データから氏名・住所・電話番号・メインのメールアドレス・パスワード等をマスク処理したテスト用データを複製していたが、ログイン時の認証用パスワードが固定文字列で運用され、一部項目ではマスク処理の未実施期間があった（同）。
- 原因は、ベーシック認証等の認証情報を長期間変更しなかったことで、同社は「不適切な認証情報管理および権限運用」が原因としている（同）。
- アクセスされ得た期間は2013年（環境構築時）から2026年8月13日まで。最大件数は902,576件で、外部へ流出した事実や悪用・二次被害は確認されていない（同）。
- 7月17日の行政機関からの照会を受けた調査で判明し、8月13日に対象環境の遮断とアクセス制御の強化、9月4日にセキュリティ管理マニュアル等を整備した（同）。
- 環境内の項目には、ユーザーID、GitHub ID（2017年9月〜2026年7月）、生年月日、性別、職歴、学歴、スキルチェック受験・学習実績、応募履歴・求人希望条件、法人取引先の担当者情報（部署名、役職、氏名カナ、携帯電話番号など）が含まれる（同）。

### わかっていないこと

- ログ解析の結果、退職者などによる実際のアクセスや取得があったか（同社は監視とログ解析を続けるとしている）。
- 行政機関の照会のきっかけになった情報の内容。
- マスクが未実施だった項目と期間の具体的な範囲（「一部非適用期間あり」とされる請求先担当者名・スキルチェック受験者氏名など）。

### 関係しそうな既知の手口

- （考察）本番データを複製した検証環境が、本番ほど守られないまま残り続ける問題は国内でも繰り返し起きている。開発用サーバーから情報が流出したチームスピリットの件（[チームスピリット ― 開発用サーバーへの不正アクセスで情報が流出](https://color4pen.github.io/security-notes/notes/2026-11-06-teamspirit-dev-server-unauthorized-access/)）とは、本件では侵入が確認されていない点が異なる。

## 発表内容の整理

**事実（paizaの11月13日の発表による）**

| 項目 | 内容 |
| --- | --- |
| 対象 | 開発用ステージング環境（動作検証環境） |
| 不備 | ベーシック認証等の固定パスワードを長期間変更せず、退職者等が外部からアクセスし得た。一部項目でマスク未実施期間 |
| 期間 | 2013年〜2026年8月13日 |
| 件数 | 最大902,576件（アクセスされ得た件数） |
| 流出 | 確認されていない |
| 対応 | 内部専用の接続経路からのみ許可するネットワーク制御へ切替（8月13日）、権限削除運用の徹底、マスク基準の再検証、外部診断 |

**考察**

- ベーシック認証は「知っている人なら誰でも入れる」共有パスワードで、人の入れ替わりがあるたびに変えない限り、退職者の締め出しができない。13年という期間は、検証環境が棚卸しの対象から外れていたことを示している。
- 侵入が確認された事案ではないが、ログがどこまで残っているかで「流出していない」と言える根拠の強さが変わる。13年分のアクセスを検証できるかは示されていない。
- 照会から公表まで約4か月かかっており、その間に遮断と再発防止策を済ませてからの公表となった。

## 利用者・運用者がいまできること

- 利用者：paizaからの個別メールを確認する。転職・求人を装った連絡で、応募履歴やスキルチェック結果を知っているかのような内容には注意する。
- 運用者：ステージング・検証環境を含めて、インターネットから到達できる環境と、共有パスワード・ベーシック認証の使用箇所を棚卸しする。
- 運用者：本番データを検証環境に持ち込む場合、マスクの対象項目を新しい項目の追加のたびに見直す仕組みを作る。
