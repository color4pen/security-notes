# iDA「MyBRANDS」 ― 委託先のクラウド鍵が悪用され会員データが送信

## 要点

### 発表された事実

- iDAは2026年10月30日、求人サイト「MyBRANDS」のサーバー環境に第三者の不正アクセスがあり、登録した求職者と企業の担当者の情報が外部に漏えいしたおそれがあると公表した（[iDA 10月30日のお知らせ](https://ida-mode.com/lp/news/unauthorized-access-2026-10/)、内容は[IT Post](https://itpostjp.com/security/ida-mybrands-unauthorized-access-135000/)の整理で確認）。
- サービス停止中に脆弱性への対応を進めていたところ、10月21〜22日に委託先が使っていたクラウドの管理用アクセスキーが不正に使われ、複製したデータベースから外部へデータが送られた記録があることが10月26日にわかった（同）。
- 送られたデータの中身は確認できていないため、預かっていた情報すべてを対象としている。対象は最大約13万5,000アカウント（退会者を含む）（同）。
- 氏名・メールアドレス・電話番号・住所は暗号化して保存していたが、暗号を解く鍵も取得されたおそれがある（同）。
- クレジットカードや銀行口座の情報は預かっていない。二次被害は確認されていない。MyBRANDS以外の同社サービスは対象外（同）。

### わかっていないこと

- 管理用アクセスキーが第三者に渡った経緯
- 実際に送られたデータの範囲
- 「サービス停止中に対応していた脆弱性」の内容と、今回の不正利用との関係
- パスワードの「変換した値」の方式（ハッシュ化の方式など）
- サービス再開の時期

### 関係しそうな既知の手口

- 盗んだクラウドのアクセスキーでスナップショットやデータベースの複製を作り、外部へ持ち出す手口（考察）。

## 概要

- 求人サイト「MyBRANDS」で、委託先のクラウド管理用の鍵が悪用され、データベースの複製から外部へデータが送られた。
- 中身を確認できないため、求職者と企業担当者の全アカウント（最大約13万5,000件）が対象。
- 暗号化していた個人情報も、復号の鍵まで取られたおそれがある。

> この記事では、公式発表・報道で確認できた内容を「事実」、筆者の推測や意見を「考察」として分けて書いています。確認できなかった情報は書いていません。

## 発表内容の整理

**事実（iDAのお知らせによる。IT Postの整理で確認）**

| 項目 | 内容 |
| --- | --- |
| 対象者 | MyBRANDSに登録した求職者と企業の担当者（退会者を含む） |
| 件数 | 最大約13万5,000件（アカウント数、10月30日時点） |
| 漏えいのおそれがある情報 | 氏名、メールアドレス、電話番号、登録プロフィール（職歴など）、ログイン用パスワード（変換した値）など。登録内容により異なる |
| 含まれない情報 | クレジットカード・銀行口座の情報（預かっていない） |
| 暗号化 | 氏名・メールアドレス・電話番号・住所は暗号化して保存。復号の鍵も取得されたおそれ |
| 対応 | サービスは停止を継続し、安全を確認できるまで再開しない。個人情報保護委員会へ報告、警察に相談。委託先と原因を調査 |
| 利用者へのお願い | 同じパスワードを他のサービス（企業担当者は社内システムも）で使っている場合はそちらを変更。MyBRANDS側の手続きは不要 |
| 問い合わせ | 求職者 mybrands-inquiry@ida-mode.com、企業担当者 mybrands-inquiry-biz@ida-mode.com |

**考察**

暗号化していたのに復号の鍵も取得されたおそれがある、という説明は、データベースと鍵の両方に届く権限を一つのアクセスキーが持っていた可能性を示している。委託先が使う管理用キーの権限の広さと、その保管の仕方が今後の調査結果の焦点になる（考察）。

求人サイトのため、職歴などの経歴情報が含まれる。企業の担当者も対象で、同社は社内システムのパスワード変更にも触れている。採用担当者を名乗る、または応募者を名乗る標的型のメールに使われるおそれがある（考察）。

## 関係しそうな既知の手口

**事実（既知の知見）**

- JPCERT/CCは、国内で相次ぐ不正アクセスの手口として、他のシステムの侵害で盗んだAPIキーを使う攻撃を挙げ、APIトークンには必要最小限の権限だけを与え、漏えいが疑われるものはすぐ無効化できるようにするよう勧めている（[JPCERT/CC 注意喚起](https://www.jpcert.or.jp/at/2026/at260030.html)）。

**考察**

クラウドの管理用キーが使えると、本番データベースに直接触れなくても複製を作って持ち出せる。データベースへの通常のアクセス記録だけを見ていると気づきにくいため、複製やスナップショットの作成、外部共有といった管理操作の記録を監視することが重要になる（考察）。

## 利用者・運用者がいまできること

- MyBRANDSに登録したことがある人（退会者を含む）は、iDAからのメールを確認し、同じパスワードを使っている他のサービスのパスワードを変更する。
- 本件に便乗した連絡に注意する。同社は、本件のメールにリンクを載せておらず、ログインのコードやパスワード、金銭のやりとりを尋ねることはないとしている。
- 委託先にクラウド環境の管理を任せている事業者は、委託先が持つアクセスキーの権限・有効期限・保管場所と、暗号化鍵がデータと同じ権限で取得できないかを点検する。
