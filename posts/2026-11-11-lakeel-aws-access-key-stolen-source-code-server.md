# ラキール ― 窃取されたAWSアクセスキーで顧客環境に不正アクセス

## 要点

### 発表された事実

- ラキールは2026年11月11日、同社が利用するAWSの一部環境で11月10日に不正アクセスを確認し、外部とのネットワーク遮断などを行ったと発表した。顧客には個別に状況を報告している（[ラキール 11月11日発表（第1報）](https://www.lakeel.com/ja/news-event/news/detail_20261111.html)）。
- 11月13日の第2報で、同社が運用するソースコード管理システムのサーバーで、アクセス制御に関するセキュリティ設定の不足を突かれ、AWS環境で使うアクセスキーを窃取されたことが発端だと特定した（[ラキール 11月13日発表（第2報）](https://www.lakeel.com/ja/news-event/news/detail_20261113.html)）。
- 確認された被害（同）：
  - 顧客1社の環境で、従業員等140名分の氏名・メールアドレスが漏えいした（11月12日に確認）。
  - 別の顧客1社の環境で、第三者によるサーバーへの侵入や不正なユーザーの作成が行われた。
  - そのほか一部の顧客環境でも不正アクセスの形跡があるが、具体的な被害は見つかっておらず調査中。
- 窃取されたアクセスキーは無効化・更新した。AWSの協力を得て各顧客環境のログ調査を続けており、安全を確認できた顧客から順次サービスを再開している（同）。

### わかっていないこと

- ソースコード管理システムの製品名と、「アクセス制御に関する設定の不足」の具体的な内容（認証なしで公開されていたのか、など）。
- アクセスキーがどこに置かれていたか（リポジトリ内のコードや設定ファイルか、サーバー上か）。
- アクセスキーの権限の範囲と、なぜ複数の顧客環境に届いたのか。
- 侵入が始まった時期と、影響を受けた顧客の社数。
- 不正に作成されたユーザーの用途と、その後の活動。

### 関係しそうな既知の手口

- （考察）公開状態のGitサーバーやソースコードに残ったクラウドのアクセスキーを探して悪用する手口は、国内外で繰り返し起きている。国内でも、委託先のソースコードに残った認証情報が悪用された[アップルワールドの事例](/security-notes/notes/2026-11-13-appleworld-rikisha-easy-rez-server-compromise/)があった。
- （考察）SaaSや受託運用の事業者が1つの鍵で複数の顧客環境を管理していると、鍵1本の漏えいが顧客全体への侵入につながる。

> この記事では、公式発表・報道で確認できた内容を「事実」、筆者の推測や意見を「考察」として分けて書いています。確認できなかった情報は書いていません。

## 登場する組織・サービス

- **株式会社ラキール**：企業のシステム刷新（DX）を助けるソフトと、導入・運用の支援を提供する会社（[会社概要](https://www.lakeel.com/ja/company/about.html)）。今回、盗まれたAWSのアクセスキーを使われ、顧客のクラウド環境に不正アクセスがあったと発表した（[第1報](https://www.lakeel.com/ja/news-event/news/detail_20261111.html)）。
- **AWS**：Amazonが提供するクラウドサービス。アクセスキーは、プログラムからAWS上の資源を操作するための鍵で、漏れると顧客環境にも入られる場合がある。

## 発表内容の整理

**事実（ラキールの第2報による）**

| 対象 | 状況 |
| --- | --- |
| 顧客A社の環境 | 従業員等140名分の氏名・メールアドレスが漏えい |
| 顧客B社の環境 | サーバーへの侵入、不正なユーザーの作成 |
| その他一部の顧客環境 | 不正アクセスの形跡あり、具体的な被害は未発見（調査中） |
| ラキールの対応 | アクセスキーの無効化・更新、AWSと協力したログ調査、順次再開 |

**考察**

- 侵入の入口はAWSではなく、開発用のソースコード管理サーバーだった。開発基盤のアクセス制御はサービス本体ほど厳しく見られないことが多いが、そこに本番環境の鍵が置かれていれば、実質的には本番の入口になる。
- 「不正なユーザーの作成」は、鍵を無効化しても侵入者が残れるようにする典型的な手順である。顧客側では、ラキールの鍵の更新とは別に、自社環境に見覚えのないIAMユーザーやロール、アクセスキーがないかを確かめる必要がある。
- 顧客企業から見ると、運用を任せた事業者の開発環境という、直接見えない場所が侵入口になった委託先経由の事案である。

## 利用者・運用者がいまできること

- ラキールのAWS環境を使う顧客：自社環境のIAMユーザー・ロール・アクセスキーの一覧を確認し、11月10日前後に作られたものや見覚えのないものを調べる。CloudTrailのログを保全する。
- 開発・運用事業者：ソースコード管理サーバーがインターネットから認証なしで見えないか確認する。リポジトリやサーバー上にクラウドの長期アクセスキーを置かず、顧客環境ごとに権限を分けた短期の認証情報にする。
