# ローソンID ― アプリで本人に情報を表示する仕組みが悪用され215万5345件が漏えい、9月中旬の不正アクセスが判明したのは10月7日

## 要点

### 発表された事実

- ローソンは2026年10月8日、アカウントサービス「ローソンID」と「ローソンアプリ予約」が第三者による不正アクセスを受け、顧客の個人情報の一部が漏えいしたと公表した（[ローソンのお知らせ](https://www.lawson.co.jp/contents/cont07/1533174_3310.html)）。
- 10月7日に実施した調査の中で、9月12日から14日の間に「ローソンID」が、9月17日に「ローソンアプリ予約」が不正アクセスを受けていたことが判明した（同）。
- ローソンIDでは215万5345件のメールアドレスと氏名、プレゼントの応募などで入力していた場合は性別・電話番号・住所・メルマガ取得情報が漏えいした。ローソンアプリ予約では26件の氏名・電話番号・クレジットカード番号の一部が漏えいした（同）。
- 原因は「ローソンアプリに関連するシステムが不正に利用されたこと」で、「本来、アプリ上で利用者本人に対し情報を表示するためのセキュリティ機構」が不正アクセスを受けたとしている。本件以外の不正アクセスやマルウェア感染はないことを確認済みという（同）。
- 不審なアクセス元をブロックし、ローソンアプリ予約の機能を停止した。予約機能は10月中旬の再開を予定している。個人情報保護委員会へ報告済み（同）。

### わかったこと

- 【2026-10-10追記】日経クロステック（10月9日）によると、ローソンはシステムで不審なアクセスを常時監視していたが今回の不正アクセスは検知できず、人手による定期調査で発見したという（[日経クロステック](https://xtech.nikkei.com/atcl/nxt/column/18/00001/12086/)）。10月7日の「調査」はこの定期調査とみられる。

### わかっていないこと

- 「本人に情報を表示するためのセキュリティ機構」が具体的に何か（アプリが使うAPIか、ログイン状態を確認する仕組みか）と、どう突破されたか
- 3日間で215万件を取得した方法（他人のIDを指定して取得したのか、何らかの認証情報を悪用したのか）
- 9月中旬の不正アクセスが常時監視で検知されなかった理由と、定期調査で何を見て気づいたのか（【2026-10-10追記】人手による定期調査で発見したことは報道で判明）
- ローソンIDとローソンアプリ予約の2件が同じ手口か
- 漏えいしたクレジットカード番号の「一部」の桁数

### 関係しそうな既知の手口

- （考察）「本人に情報を表示する」ための仕組みが悪用されて大量の情報が漏れたという説明は、アプリが使うAPIで、要求してきた利用者が本当にそのデータの持ち主かを確かめる処理（認可）が欠けていた場合に起きる漏えいと似ている。OWASPはこの欠陥を「Broken Object Level Authorization（BOLA）」としてAPIの最も重大なリスクの1位に挙げている。本件の原因がこれに当たるかは公表されていない。

## 概要

- コンビニ大手ローソンの共通アカウント「ローソンID」が9月12日から14日に不正アクセスを受け、215万5345件の氏名・メールアドレスなどが漏れた。
- 攻撃者は、アプリで利用者本人に自分の情報を表示するための仕組みを悪用したとされる。予約・決済サービス「ローソンアプリ予約」でも9月17日に26件が漏れ、カード番号の一部が含まれる。
- 不正アクセスがあったのは9月中旬だが、判明したのは10月7日の調査で、公表は10月8日。具体的な手口は公表されていない。

> この記事では、公式発表・報道で確認できた内容を「事実」、筆者の推測や意見を「考察」として分けて書いています。確認できなかった情報は書いていません。

## 発表内容の整理

**事実（10月8日のお知らせ）**

| サービス | 件数 | 漏えいした情報 |
| --- | --- | --- |
| ローソンID（ローソンのアプリやWebサービスを使うためのアカウント） | 215万5,345件 | メールアドレス、氏名。プレゼントの応募などで入力していた場合は性別、電話番号、住所、メルマガ取得情報 |
| ローソンアプリ予約（季節の催事商品をアプリで事前に予約・決済するサービス） | 26件 | 氏名、電話番号、クレジットカード番号の一部 |

- 原因：ローソンアプリに関連するシステムが不正に利用された。本来、アプリ上で利用者本人に情報を表示するためのセキュリティ機構が、第三者による不正アクセスを受けた。
- 本件以外の不正アクセス、マルウェアの感染はないことを確認済み。
- 現時点で、不正利用や二次被害は確認されていない。
- 対応：不審なアクセス元のブロック、ローソンアプリ予約機能の停止、アプリ上での告知、対象者への個別メール（送信元「ローソンIDメール」lawson_id@mailservice.lawson.jp）、関係機関への報告。
- 再発防止策：対象システムのセキュリティ対策強化、監視体制の強化、インシデント対応体制の強化。
- 問い合わせ：ローソンカスタマーセンターの専用受付フォーム。

**考察**

「本人に情報を表示するための仕組み」から215万件が出ていったという説明からは、攻撃者が自分のアカウントでは見られないはずの他人の情報を、その仕組みを通じて繰り返し取り出したことが想像できる。会員登録時の氏名・メールアドレスに加え、プレゼント応募で入力した人の住所や電話番号まで含まれているので、アプリのマイページなどに表示される会員情報がひととおり読めた可能性がある。ただしローソンは手口を公表しておらず、パスワードの漏えいの有無にも触れていない。

不正アクセスの期間は9月12日から14日の3日間と短いが、判明したのは3週間以上たった10月7日の調査だった。ローソンは調査のきっかけを書いていない。大量のデータ取得がその場で検知されなかったとすれば、再発防止策に「監視体制の強化」が挙がっているのはその反省とみられる。

【2026-10-10追記】日経クロステックの報道で、常時監視をすり抜け、人手による定期調査で見つかったことがわかった。3日間で215万件という量の取得が自動の監視にかからなかったことになり、1件ずつの要求は正規の利用と見分けにくい形だった可能性がある（考察）。どのような形の通信だったかは公表されていない。

10月に入ってからは、国内で会員アプリからの大量流出の公表が相次いでいる（[焼肉きんぐ公式アプリ](/security-notes/notes/2026-10-06-yakiniku-king-app-10-7m-members-breach/)、[ミスターマックス](/security-notes/notes/2026-10-07-mrmax-app-online-store-1-73m-members/)、[セイコーマートアプリ](/security-notes/notes/2026-10-02-seicomart-app-member-data-breach/)など）。どれも侵入の手口ははっきり公表されておらず、同じ攻撃者や同じ手口かどうかはわからない。

## 関係しそうな既知の手口

**事実（既知の知見）**

- OWASP API Security Top 10（2023年版）は、APIが受け取ったIDのデータについて、要求した利用者にそのデータを見る権限があるかを確かめない欠陥を「API1:2023 Broken Object Level Authorization」として1位に挙げている（[OWASP](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/)）。
- JPCERT/CCは10月8日、国内組織で不正アクセスによる情報漏えいが相次いでいるとして注意喚起を出した。類型の一つ「API経由での不正な操作」として、一般公開しているスマートフォンアプリを解析してAPIのエンドポイントやキーを特定する手口、本来画面操作では実行できない内部APIへの攻撃（ヘッダーの有無の切り替えや不正な形式の認証トークンで応答の違いを確かめる、など）の報告を受けているとしている。対策として、APIの単位時間あたりのリクエスト件数の制限や、非公開APIを含む各エンドポイントでのアクセス制御を挙げている（[JPCERT/CC](https://www.jpcert.or.jp/at/2026/at260030.html)）。

**考察**

- **会員IDの付け替えによる他人の情報の取得**：アプリのAPIが、ログイン中の利用者を基準にせず、要求に含まれる会員番号などを信じて情報を返す作りだと、番号を順に変えるだけで全会員の情報を引き出せる。3日間で200万件を超える取得は、こうした機械的な繰り返しと整合する。本件で使われた手口は公表されていない。
- **本人確認用トークンの悪用**：アプリが本人の情報を表示するために使う認証トークン（ログイン状態を示す値）の検証に不備があると、他人になりすまして情報を取得できる。ローソンが「セキュリティ機構」という言葉を使っている点からは、こちらの可能性も考えられる。JPCERT/CCが挙げる「アプリを解析してAPIを特定し、認証トークンの形式を変えて応答の違いを確かめる」手口は、こうした不備を探す手順そのものに当たる。本件がJPCERT/CCの注意喚起の対象事例に含まれるかはわからない。

## 利用者・運用者がいまできること

**事実（発表に基づく）**

- 対象者には「ローソンIDメール」（lawson_id@mailservice.lawson.jp）から順次、個別に案内が届く。
- ローソンIDに登録したメールアドレス・電話番号・住所宛ての、不審なメール・SMS・電話に注意する。

**考察（利用者向け）**

- ローソンを名乗るポイント付与・当選・アカウント停止の連絡が届いたら、リンクを開かずにアプリや公式サイトから確認する。氏名・メールアドレスがそろって漏れているため、本名入りのそれらしいメールが届くおそれがある。
- 案内メールの送信元を装った偽メールも考えられるので、案内に書かれたリンクからパスワードやカード情報を入力しない。
- ローソンアプリ予約でカードを使った人は、カードの利用明細を確認する（漏れたのは番号の一部とされている）。

**考察（アプリ・APIの運用者向け）**

- 会員情報を返すAPIで、要求に含まれる会員IDではなく、ログイン中の利用者（サーバー側で検証したトークン）を基準にデータを返しているかを確認する。
- 1つのアカウントやアクセス元から短時間に大量の会員情報が要求されたら、検知・遮断できるようにする（JPCERT/CCもAPIのリクエスト件数の制限を推奨している）。本件では不正アクセスから判明まで3週間以上かかっている。
- 公開しているアプリの中に、APIのキーや内部APIのエンドポイントが埋め込まれていないかを確認する。アプリは誰でも入手して解析できる前提で設計する。
