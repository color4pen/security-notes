# ジャパンタイムズ ― 使用終了したファイルサーバーがランサムウェア被害

## 要点

### 発表された事実

- 株式会社ジャパンタイムズと株式会社ニューズ・ツー・ユーホールディングスは2026年10月16日、9月18日にグループが管理するサーバーがランサムウェアを用いたサイバー攻撃を受けたことを確認したと公表した（[第2報](https://www.japantimes.co.jp/press/2026/10/16/notice-ransomware-incident-second-report-jp/)）。
- 10月15日、攻撃者がグループから窃取したと主張するデータが、外部のWebサイトで公開されたことを確認した（同）。
- 対象は、グループが2022年8月まで使っていた管理部門用のファイルサーバー。公開されたデータには、2001年から2022年8月までのグループの人事関連情報と取引先に関する情報が含まれている可能性がある。2022年8月以降のデータは含まれていない（同）。
- 「Japan Times Online」などの電子版、購読者データベース、決済システムなどは独立したインフラで運用している（同）。

### わかっていないこと

- 公開されたデータの中身と範囲（誰の、どの情報か）
- 攻撃者（ランサムウェアグループ）の名前
- 使い終えたファイルサーバーが、2026年9月時点でどこに、どういう状態で残っていたのか
- 侵入経路
- 金銭の要求の有無

### 関係しそうな既知の手口

- （考察）暗号化に加えて盗んだデータをリークサイトで公開し、支払いを迫る「二重脅迫」の型。京王電鉄グループや池上通信機でも、同じように犯行側の公開・主張が続報のきっかけになっている。

## 概要

- 英字紙ジャパンタイムズのグループで、9月18日にランサムウェア攻撃が確認され、10月15日に攻撃者が盗んだと主張するデータの公開が確認された。
- 対象は2022年8月に使うのをやめた管理部門のファイルサーバーで、約20年分の人事関連情報と取引先の情報が含まれる可能性がある。
- 電子版や購読者データベース、決済システムは別のインフラで、影響は示されていない。公開データの中身は照合中。

> この記事では、公式発表・報道で確認できた内容を「事実」、筆者の推測や意見を「考察」として分けて書いています。確認できなかった情報は書いていません。

## 発表内容の整理

**事実（第2報）**

| 項目 | 内容 |
| --- | --- |
| 攻撃の種類 | ランサムウェアを用いたサイバー攻撃（9月18日に確認） |
| 対象 | 2022年8月まで利用していた管理部門用ファイルサーバー |
| 公開 | 10月15日、攻撃者が窃取したと主張するデータが外部のWebサイトで公開 |
| 含まれる可能性がある情報 | 2001年〜2022年8月のグループの人事関連情報、取引先に関する情報 |
| 含まれないもの | 2022年8月以降のデータ |
| 別インフラのもの | 「Japan Times Online」などの電子版、購読者データベース、決済システムなど |
| 対応 | 発覚直後に対象サーバーを隔離。複数の外部専門機関の支援で、公開データの照合とログ監視を継続 |
| 届け出 | 個人情報保護委員会と管轄警察署などに速報し、法令に基づく報告を継続 |
| 本人への連絡 | 公開データに情報が含まれていると判明した取引先・関係者に順次個別に連絡。連絡先がわからない人は専用窓口（incident-support@news2u.co.jp）で照会を受ける |

**事実（第1報の報道）**

- ITmediaは10月2日、ジャパンタイムズがグループ会社の管理するサーバーの一部に不正アクセスがあったと発表し、電子版や購読者データベース、決済システムは独立した別のインフラで運用しているため影響は確認していないと伝えた（[ITmedia NEWS](https://www.itmedia.co.jp/news/article/2610/02/2000001975/)）。

**考察**

第1報では「不正アクセス」とだけ書かれ、ランサムウェアの名前は出ていなかった。第2報でランサムウェアだったことと対象サーバーの用途が明らかになったのは、攻撃者側のデータ公開が確認されたあとだ（考察）。公表の中身が、自社の調査よりも犯行側の動きに押されて具体的になった形に見える。

対象が「2022年8月まで利用していた」サーバーだという点は重い。使わなくなってから約4年、2001年からの人事関連情報を載せたまま、攻撃者が届く状態で残っていたことになる（考察）。どういう形で残っていたか（電源が入ったままか、ネットワークにつながっていたか）は公表されていない。

## 関係しそうな既知の手口

**事実（既知の知見・同種事例）**

- 京王電鉄グループでは、9月のランサムウェア攻撃から3週間後に、Qilinが情報の一部を公開したと主張した（[京王電鉄グループの記事](/security-notes/notes/2026-10-18-keio-group-ransomware-qilin-leak-claim/)）。
- 池上通信機は、外部からの通報でファイルの暗号化とリークサイトへの情報公開が発覚した（[池上通信機の記事](/security-notes/notes/2026-10-05-ikegami-tsushinki-ransomware-leak-site/)）。

**考察**

- **「使い終えた」は「消した」ではない**：システムの移行後も、古いファイルサーバーを念のため残しておくことはよくある。だが、更新もされず、誰も見ていないサーバーほど、侵入されても気づきにくく、パッチも当たっていない可能性が高い。保管の必要がなければ消し、必要ならネットワークから切り離して保管する、という整理が要る。
- **人事情報は長く効く**：2001年からの人事関連情報には、退職者も含めた氏名や連絡先などが入っている可能性がある。取引先の情報と合わせて、グループや取引先を装ったメールに使われやすい。

## 利用者・運用者がいまできること

**事実（発表に基づく）**

- グループや関係者を装った不審なメールを受け取ったら、URLを開かず、添付ファイルも開かない（第2報）。
- 2001年〜2022年8月にグループで働いていた人や取引のあった人で、連絡が来ず心配な場合は、専用窓口（incident-support@news2u.co.jp）に照会できる（第2報）。

**考察（運用者向け）**

- 移行で使わなくなったサーバーやストレージの一覧を作り、残す理由・保管期限・ネットワーク接続の有無を確認する。
- 古い業務データは、人事・経理など部門ごとに保管期限を決め、期限が来たら削除まで確認する。
- ランサムウェアのリークサイトの監視（自社名の掲載の確認）を外部サービスなどで行い、犯行側の公開に先回りできる体制をつくる。
