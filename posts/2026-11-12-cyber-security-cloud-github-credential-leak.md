# サイバーセキュリティクラウド ― GitHubに不正アクセス、顧客情報漏えいの恐れ

## 要点

### 発表された事実

- サイバーセキュリティクラウド（東証グロース、4493）は2026年11月12日、ソフトウェア開発に使うGitHub上の同社管理領域への不審なアクセスを確認し、保存されていた個人情報に漏えいの恐れがあると発表した（[サイバーセキュリティクラウド](https://www.cscloud.co.jp/news/info/20261112-2/)）。
- 外部機関からの情報提供で、従業員が業務で使っていたGitHubの認証情報1件が外部に流出していたことがわかった。アクセスログを調べ、その認証情報を使った第三者によるとみられる過去の不審なアクセスを11月5日に確認した（同）。
- 確認できるアクセスログの期間や記録内容に制約があり、認証情報が有効だった期間全体のアクセス状況は確認できていない（同）。
- 漏えいの恐れがあるのは、一部の顧客に関する情報（企業名、氏名、メールアドレス等）と「サービス利用に伴う通信関連情報」。範囲と対象者は調査中（同）。
- 本件に起因するサービスへの不正アクセスや不正操作、二次被害は確認されておらず、サービスとセキュリティ機能への影響もないとしている（同）。

### わかっていないこと

- 認証情報が流出した原因と経路（端末の感染か、どこかへの誤掲載かなど）。
- 流出した認証情報の種類（パスワード、個人用アクセストークン、SSH鍵など）と、有効だった期間。
- 「通信関連情報」の具体的な中身と、対象となる顧客・人数。
- GitHub上に保存されていた他サービスの認証情報が悪用されたかどうか。
- 外部専門機関によるフォレンジック調査の結果。

### 関係しそうな既知の手口

- （考察）開発基盤の認証情報を足がかりにした侵入は国内でも続いている。[ラクスル](https://color4pen.github.io/security-notes/notes/2026-11-09-raksul-data-submission-system-credentials-abuse/)や[Shippio](https://color4pen.github.io/security-notes/notes/2026-11-04-shippio-platform-internal-tool-credential-abuse/)では認証情報の悪用が、[チームスピリット](https://color4pen.github.io/security-notes/notes/2026-11-06-teamspirit-dev-server-unauthorized-access/)では開発用サーバーへの侵入が公表された。

**考察**

- 本来ソースコードを置く場所に、顧客の企業名や氏名、通信に関する情報が置かれていたことが今回の被害範囲を広げている。テスト用のデータや設定ファイル、ログをリポジトリに入れてしまう運用は珍しくなく、どの種類のファイルだったのかが今後の焦点になる。
- 同社が「GitHub上に保存されていた、他のサービスに関する各種認証情報」を変更したと書いていることから、リポジトリ内に他サービスの鍵やパスワードもあったことがうかがえる。漏れた認証情報が1件でも、そこから読める秘密情報が多ければ影響は連鎖する。
- ログの保存期間の制約で「有効だった期間全体」を確認できていない点は、GitHubの監査ログやクローン履歴の保持期間を事前に延ばしておく重要性を示している。
- WAFなどを提供する企業の開発環境である以上、顧客は自社の設定情報やWAF経由の通信情報が含まれていないかを気にするはずで、「通信関連情報」の具体的な説明が求められる。

## 利用者・運用者がいまできること

- 顧客企業：同社からの個別連絡を確認し、同社サービスに登録している管理者アカウントのパスワード変更や多要素認証の有無を見直す。同社を装った不審なメールにも注意する。
- 開発組織一般：GitHubの個人用アクセストークンやSSH鍵の棚卸しを行い、有効期限と権限範囲を絞る。組織単位でSSOと多要素認証を必須にする。
- リポジトリに顧客データや本番の秘密情報を置かない。シークレットスキャンを有効にし、過去の履歴に残った秘密情報も無効化する。
- 監査ログを外部に転送し、保持期間を長めに確保しておく。
