# リゾートトラスト ― 管理するウェブサイトに約3時間の「異常な作動」、グループ会員約2万6千件とザ・カハラ・横浜の予約者約3万6千件が漏洩

## 要点

### 発表された事実

- リゾートトラスト株式会社は2026年10月9日、同社が管理するウェブサイトに外部の第三者から不正アクセスがあり、サーバに保管されていた顧客の個人情報の一部が外部に漏洩したと公表した（[リゾートトラストの発表](https://www.resorttrust.co.jp/wp_api/wp-content/uploads/2026/10/20261009.pdf)）。
- 10月5日20時30分ごろから23時30分ごろまで当該ウェブサイトのシステムに異常な作動があったことを翌6日に認知し、調査の結果、10月7日に不正アクセスによる情報漏洩を確認した。直ちに不正アクセスを遮断した（同）。
- 漏洩が確認された情報は、一部のグループ会員の情報約2万6千件と、ザ・カハラホテル＆リゾート 横浜の予約者の情報約3万6千件（同）。
- 当該システムには、利用履歴・医療情報・クレジットカード情報・銀行口座情報・メールアドレス・本人確認書類等は含まれていない（同）。
- 全国のホテルと各施設の運営への直接的な影響はなく、予約や滞在に支障はない。外部のセキュリティ専門機関と詳細な調査をしている（同）。

### わかっていないこと

- 漏洩した情報の具体的な項目（氏名・住所・電話番号などが含まれるか）
- 不正アクセスを受けた「ウェブサイト」が何のサイトで、なぜ会員情報と予約者情報が同じシステムにあったか
- 侵入経路と、改修するとされた「対象システムの脆弱性」の内容
- 2つの件数（約2万6千件・約3万6千件）の重複の有無と、実際の人数
- 不正アクセスが10月5日夜の約3時間だけだったのか、それ以前から始まっていたのか

### 関係しそうな既知の手口

- （考察）JPCERT/CCが10月の注意喚起で挙げた類型のうち、公開Webサーバーへの既知の脆弱性の悪用（ケースA）や、公開WebサーバーからアクセスできるアプリケーションサーバーへのWebシェル設置（ケースD）は、「ウェブサイト」を入口にサーバ上の保管データへ届いた本件の説明と矛盾しない。ただし、本件がどの類型に当たるかは公表されていない。

## 概要

- 会員制リゾートホテルなどを運営するリゾートトラストの、同社が管理するウェブサイトが不正アクセスを受け、サーバに保管されていた会員と予約者の情報が漏洩した。
- システムの異常な作動は10月5日夜の約3時間で、認知は翌日、漏洩の確認は2日後、公表は4日後だった。
- 公表資料は含まれない情報（カード、口座、メールアドレス、本人確認書類など）を列挙する一方、漏洩した項目そのものは書いていない。

> この記事では、公式発表・報道で確認できた内容を「事実」、筆者の推測や意見を「考察」として分けて書いています。確認できなかった情報は書いていません。

## 発表内容の整理

**事実（リゾートトラストの発表）**

| 項目 | 内容 |
| --- | --- |
| 侵入箇所 | 同社が管理するウェブサイト（サイト名は記載なし） |
| 漏洩が確認された情報 | 一部のグループ会員の情報 約2万6千件、ザ・カハラホテル＆リゾート 横浜の予約者の情報 約3万6千件 |
| 含まれない情報 | 利用履歴、医療情報、クレジットカード情報、銀行口座情報、メールアドレス、本人確認書類等 |
| 営業への影響 | 全国のホテル・施設の運営に直接の影響はなく、予約・滞在に支障なし |
| 調査 | 外部のセキュリティ専門機関と連携して詳細調査中 |
| 再発防止策 | 調査結果を踏まえ、対象システムの脆弱性の改修、監視体制の強化、ネットワークアクセス権限の厳格な見直し |
| 対象者への連絡 | 漏洩の対象と確認された顧客に順次個別に案内 |
| 業績への影響 | 重要な影響が明らかになれば速やかに開示 |
| 問い合わせ | リゾートトラストインフォメーションセンター（RIC）0120-350-132（10月10日〜12日と平日の9:00〜17:00） |

**考察**

公表資料は「含まれていない情報」を細かく挙げる一方で、漏洩した項目を一つも書いていない。メールアドレスが含まれないと明記しているのは珍しく、他社の会員情報の漏洩で典型的な「メールアドレスと氏名」の組み合わせとは中身が違う可能性がある（考察）。ただ、対象者に注意を呼びかけている内容は「不審な連絡やメッセージ」で、電話や郵送での連絡に使える情報が含まれているかどうかは、対象者が自分で判断できない状態になっている。

再発防止策に「対象システムの脆弱性の改修」と並んで「ネットワークアクセス権限の厳格な見直し」が入っている点も手がかりになる。ウェブサイトを入口にして、本来そのサイトからは届かなくてよいサーバやデータに届いた可能性を同社自身が想定している、と読める（考察）。会員情報と、特定の1ホテルの予約者情報が同じシステムに保管されていた理由も、この点に関わるかもしれない。

異常な作動が約3時間と限られ、翌日に認知できていることから、何らかの監視や異常検知は働いていたとみられる（考察）。一方で、漏洩の確認までさらに1日、公表までは認知から3日かかっている。

## 関係しそうな既知の手口

**事実（既知の知見）**

- JPCERT/CCは10月8日に公開し9日に更新した注意喚起で、国内組織で相次ぐ漏えいの類型として、(A)標的ごとにさまざまな既知の脆弱性を探して悪用を試みるもの、(B)API経由の不正な操作、(C)MetabaseのSQLインジェクション（CVE-2026-72898）、(D)公開Webサーバーからアクセスできるアプリケーションサーバー上へのWebシェル設置を示した（[JPCERT/CC](https://www.jpcert.or.jp/at/2026/at260030.html)、[各機関の注意喚起の記事](/security-notes/notes/2026-10-11-jpcert-nco-ipa-alerts-domestic-breach-wave/)）。
- 内閣官房国家サイバー統括室は10月9日、ウェブシステム等の管理、サプライチェーンを通じた侵害への対策、データの管理の3点で対策の徹底を求めた（[NCO](https://www.cyber.go.jp/pdf/press/taiou.pdf)）。

**考察**

- **キャンペーンや予約のサイトは、本体より古くなりやすい**：ホテルやリゾートの運営会社は、施設ごと、キャンペーンごとにウェブサイトを持つことが多い。本体の会員システムほど更新や点検の手が回らないサイトが、会員情報の置かれたサーバにつながっていると、そこが入口になる。本件のサイトがどういう性格のものかは公表されていないが、同業他社にとって点検の観点になる。
- **「含まれないもの」より「含まれるもの」を**：対象者が二次被害を見積もるには、漏洩した項目の一覧が必要になる。個別の案内で項目が示されるのか、続報で公表されるのかは、まだわからない。

## 利用者・運用者がいまできること

**事実（発表に基づく）**

- 心当たりのない不審な連絡やメッセージが届く可能性がある。不審に感じたら、記載されたURLや電話番号にはアクセスせず、相手が名乗る企業や機関の公式サイトなどから正しい連絡先を確認する。
- 問い合わせはリゾートトラストインフォメーションセンター（RIC）で受け付けている。

**考察（利用者向け）**

- 会員制リゾートの会員やリゾートホテルの予約者であることは、それ自体が「資産のある人」を狙う詐欺の材料になりうる。会員権の買い取りや予約の変更、返金を名目にした電話や郵便物には、同社の公式の連絡先にかけ直して確かめる。
- メールアドレスは含まれないとされているため、電話や郵送、SMSでの連絡に特に注意する（考察）。

**考察（運用者向け）**

- 自社が管理するウェブサイト（キャンペーンサイト、施設ごとのサイト、予約フォームなど）を一覧にし、それぞれがどのサーバ・データベースにつながっているかを確認する。会員基盤のデータが、公開サイトのサーバから直接読める構成になっていないかを見る。
- 公表の際は、漏洩した項目を具体的に示す。含まれない項目だけでは、対象者が警戒すべき連絡の種類を判断できない。
