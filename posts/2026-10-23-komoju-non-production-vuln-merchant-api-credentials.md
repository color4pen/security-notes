# KOMOJU ― 非本番環境の脆弱性から加盟店のAPI認証情報が漏洩

## 要点

### 発表された事実

- KOMOJUは2026年10月22日、同社の決済プラットフォーム「KOMOJU」と関連システムの一部に外部から不正アクセスがあったと発表した（[KOMOJU](https://ja.komoju.com/news/1022-notice/)）。
- 10月13日夕方以降、外部の第三者が同社の非本番環境に不正アクセスした。14日早朝に不審なアクセスの増加を検知して調べたところ、非本番環境にあった脆弱性を悪用され、社内管理画面と一部のシステムに不正にログインされていたことがわかった。同日午前中に経路の遮断、関連アカウントとログイン状態の無効化、脆弱性の修正を行った（同）。
- その後の調査で、業務で使うCRMシステムへの不正アクセスも確認し、影響範囲を調査中（同）。
- KOMOJU決済システムからは、メールアドレスを含む個人データ約4100件の漏洩を確認。一部加盟店のAPI認証情報の漏洩も確認し、対象の加盟店には個別に連絡済み（同）。
- クレジットカード情報を保管するシステムは不正アクセスされたシステムと分離されており、カード情報の漏洩はない。不正決済などの二次被害は現時点で確認されていない（同）。
- 対応の影響で、10月16日にShopify連携の認証情報を更新した際にau PAY、楽天ペイ、Paidy、Naver Pay、BLIKが一時使えなくなり、18日にセブン-イレブン決済の認証情報を更新した際には購入者がバーコードを表示できない事象が起きた（同）。
- 【2026-10-27追記】KOMOJUは10月26日の第二報で、CRMシステムの件について、攻撃者が同社システムとCRMを連携するAPIキーを悪用し、CRMのAPI経由で問い合わせ記録を取得したと説明した。顧客リストの取得やデータベース全体のエクスポートは確認されていない。漏えいした可能性がある項目は、問い合わせ履歴、メールアドレス、氏名、電話番号、住所、生年月日、銀行口座情報（返金対応に関するものに限る）、本人確認書類（主に加盟店審査のためメールで送られたもの）。対象は加盟店や取引先の担当者と、問い合わせをした消費者。決済システムの約4100件とは別の事案で、カード情報は含まれず、二次被害は確認されていない。対象者への連絡と個人情報保護委員会への報告はKOMOJUが行い、加盟店側の対応は不要としている（[KOMOJU 第二報](https://ja.komoju.com/news/1026-notice/)）。

### わかったこと

- 【2026-11-23追記】KOMOJUは11月13日の最終報で調査完了を公表した。10月13日夕刻以降、本番前の最終確認用の「プレリリース環境」（本番データベースに接続し、インターネットから到達できる構成）の認証設定の不備を突かれ、職員用管理画面と一部システムに不正ログインされた。第三者はさらに、システム上にあったCRM接続用のAPIキーを使ってCRMにもアクセスした。原因として、認証・アクセス制御、認証情報の管理、開発・検証プロセス、検知体制の課題も挙げた（取りこぼし分）（[KOMOJU 最終報](https://ja.komoju.com/news/1113-notice/)、[報告書PDF](https://23804948.fs1.hubspotusercontent-na1.net/hubfs/23804948/%E3%80%90%E6%9C%80%E7%B5%82%E5%A0%B1%E3%80%91%E5%BD%93%E7%A4%BE%E3%82%B7%E3%82%B9%E3%83%86%E3%83%A0%E3%81%AB%E3%81%8A%E3%81%91%E3%82%8B%E3%82%BB%E3%82%AD%E3%83%A5%E3%83%AA%E3%83%86%E3%82%A3%E3%82%A4%E3%83%B3%E3%82%B7%E3%83%87%E3%83%B3%E3%83%88%E3%81%AB%E3%81%A4%E3%81%84%E3%81%A6.pdf)）。
- 【2026-11-23追記】影響範囲は、①KOMOJU決済システム：一部加盟店のサービスを使った消費者の約4,100件（メールアドレス、氏名、電話番号。氏名・電話番号を含むのは一部）、②CRMシステム：問い合わせをした加盟店・決済パートナーの役職員と消費者の約12,400件（問い合わせ履歴、メールアドレス、氏名、電話番号、住所、生年月日、金融機関口座情報、公的身分証明書類。口座情報・身分証を含むのは一部）。ほかに一部加盟店のAPI秘密鍵と、決済手段の提供会社との接続用認証情報が閲覧された。クレジットカード情報は含まれず、本番クラウド基盤への不審な操作やストレージからの流出、不正決済・返金・精算口座の変更、二次被害は確認されていない（同）。
- 【2026-11-23追記】対象者への個別連絡と個人情報保護委員会への報告は完了。決済手段の提供会社との接続用認証情報は各社と協議しながら順次変更している。10月16日のShopify向け決済アプリの障害と10月19日のセブン-イレブン決済のバーコード不具合は、認証情報の切り替え作業によるものだった（同）。

### わかっていないこと

- 非本番環境にあった脆弱性の内容と、非本番環境から社内管理画面・本番側のシステムにログインできた理由（認証情報の共有か、ネットワーク上のつながりか）（【2026-11-23追記】最終報で、プレリリース環境の認証設定の不備が直接の原因で、CRMにはシステム上のAPIキーで入られたと説明された）
- 約4100件の個人データの内訳（加盟店の役職員か、加盟店で買い物をした消費者か）と項目（【2026-11-23追記】最終報で、一部加盟店のサービスを使った消費者の約4,100件（メールアドレス、氏名、電話番号）と説明された）
- CRMシステムから取られた情報の範囲（【2026-10-27追記】第二報で、問い合わせ記録と添付の本人確認書類などが対象と説明された。対象人数は未公表）（【2026-11-23追記】最終報で約12,400件と公表された）
- API認証情報が漏洩した加盟店の数と、それらの認証情報が使われた形跡の有無（【2026-11-23追記】最終報でも加盟店数は示されず、不正な決済・返金・精算口座の変更は確認されなかったとされた）
- 10月14日の検知から22日の公表までの間に、加盟店や消費者にどんな案内がされたか

### 関係しそうな既知の手口

- （考察）開発・検証用の非本番環境は、本番より防御が甘くなりがちで、しかも本番と同じ認証情報や接続先を持っていることがある。決済代行事業者の加盟店APIキーが漏れると、加盟店になりすました決済・返金・取引情報の照会などに悪用されるおそれがあるため、キーの無効化と再発行が最優先になる。

## 登場する組織・サービス

- **KOMOJU**：ネットショップなどが決済を受け付けるためのプラットフォーム。今回、非本番環境の欠陥から加盟店のAPI認証情報が漏えいしたと発表した（[お知らせ](https://ja.komoju.com/news/1022-notice/)）。

## 概要

- オンライン決済代行サービス「KOMOJU」で、非本番環境の脆弱性から社内管理画面などに侵入された。
- 一部加盟店のAPI認証情報と約4100件の個人データが漏洩した。カード情報のシステムは別で、カード情報の漏洩はない。
- 認証情報の入れ替えに伴い、一部の決済手段で一時的な障害が起きた。

## 発表内容の整理

**事実（KOMOJUの発表）**

| 項目 | 内容 |
| --- | --- |
| 侵入の起点 | 非本番環境に存在していたセキュリティ上の脆弱性 |
| 不正ログインされたもの | 社内管理画面、一部のシステム |
| 不正アクセスが確認されたシステム | KOMOJU決済システム、CRMシステム |
| 漏洩（決済システム） | メールアドレスを含む個人データ約4100件 |
| 漏洩（加盟店） | 一部加盟店のAPI認証情報（個別に連絡済み） |
| 漏洩（CRM） | 調査中（【2026-10-27追記】第二報で、CRM連携用APIキーの悪用により問い合わせ記録（氏名・連絡先・生年月日、返金対応の銀行口座情報、本人確認書類など）が取得されたと説明。人数は未公表） |
| カード情報 | 漏洩なし。保管システムは分離されており、不正アクセスは確認されていない |
| 二次被害 | 不正決済などは現時点で確認されていない |
| 対応の副作用 | Shopify連携の一部決済手段の一時障害（10/16）、セブン-イレブン払いのバーコード表示不可（10/18） |

**考察**

決済代行事業者への不正アクセスで、カード情報を扱うシステムが分離されていたことは、被害を抑えた設計として評価できる。一方で、加盟店のAPI認証情報は、それだけで加盟店として決済システムを操作できる「鍵」になりうる。KOMOJUはShopify連携やセブン-イレブン決済の認証情報を自ら入れ替えており、決済手段に一時障害が出てでも鍵を替える必要があると判断したことがうかがえる（考察）。

非本番環境が入口になったにもかかわらず、社内管理画面と本番の決済システム・CRMにまで入られている。非本番環境と本番環境の間で、アカウント、シークレット、ネットワークの分離が十分でなかった可能性がある。どこで境界が越えられたのかは、同じような構成を持つSaaS事業者にとって重要な情報で、続報での説明が待たれる（考察）。

## 関係しそうな既知の手口

**事実（既知の知見）**

- JPCERT/CCは国内で相次ぐ不正アクセスについて、標的ごとに既知の脆弱性を探して悪用を試みるほか、環境設定ファイルやバックアップファイルの窃取など管理不備を突く攻撃、他システムの侵害で盗んだAPIキーの使用などが確認されているとして、不要な管理機能の公開停止や、漏えいが疑われるAPIトークンの速やかな無効化を勧めている（[JPCERT/CC](https://www.jpcert.or.jp/at/2026/at260030.html)）。

**考察**

検証環境は「本番ではないから」と外部公開や古いバージョンのまま放置されやすく、そこに本番の管理者アカウントや接続設定が残っていると、攻撃者にとっては本番への近道になる。JPCERT/CCの注意喚起が挙げる「環境設定ファイルの窃取」や「盗んだAPIキーの使用」と同じ流れが起きた可能性があるが、KOMOJUは具体的な手口を公表していない（考察）。

## 利用者・運用者がいまできること

- KOMOJUを使う加盟店は、KOMOJUからの個別連絡の有無を確認し、APIキーなどの認証情報を再発行・更新する。取引・返金の履歴に心当たりのない操作がないかを確かめる。
- KOMOJUや加盟店を名乗る不審なメールに注意する（KOMOJUはメールでパスワードや認証情報を尋ねないとしている）。
- 自社でSaaSを運営する組織は、非本番環境がインターネットから到達できるか、本番と共通の認証情報・シークレット・管理者アカウントが置かれていないかを点検する。
