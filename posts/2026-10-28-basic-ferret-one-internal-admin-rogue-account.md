# ベーシック「ferret One」 ― 内部管理機能に不正アカウントを作成された

## 要点

### 発表された事実

- 株式会社ベーシックは2026年10月27日、マーケティングプラットフォーム「ferret One」の内部管理機能に不備があり、第三者による不正アクセスが発生したと公表した（[ferret One](https://ferret-one.com/notice/20261027)）。
- 10月14日に内部の管理機能で第三者が不正にアカウントを作成し、同社は10月26日にそれを見つけて削除、経路の遮断と不備の修正を行った（同）。
- 導入企業のログイン用メールアドレスが閲覧または取得された可能性がある。氏名などそれ以外の登録情報は含まれない（同）。
- 同社と顧客のアカウント計6件で不正ログインを確認し、パスワードを初期化した。これらのアカウントを通じて閲覧・取得された情報の有無と範囲は調査中（同）。
- 2段階認証の必須化と、管理機能へのアクセス制限の強化を行った。サービスは引き続き使える（同）。

### わかっていないこと

- 内部管理機能の「不備」の具体的な内容と、外部から不正アカウントを作成できた経路
- メールアドレスが閲覧・取得された可能性のある導入企業・アカウントの数
- 不正ログインされた6アカウントで閲覧・取得された情報（ferret Oneに蓄積された問い合わせ・リード情報を含むか）
- 10月14日〜26日の12日間に不正アカウントで行われた操作

### 関係しそうな既知の手口

- （考察）運営者向けの内部管理機能で第三者がアカウントを作れたことから、管理機能のアカウント作成処理の認可不備か、管理機能そのものが外部から届く状態にあった可能性がある。6件の不正ログインの方法（取得したメールアドレスへのパスワード試行か、管理機能からの操作か）は公表されていない。

## 概要

- BtoB向けのCMS・マーケティングツール「ferret One」で、運営会社向けの内部管理機能に不備があり、第三者が不正なアカウントを作った。
- 導入企業のログイン用メールアドレスが見られた可能性があり、ベーシック社内と顧客のアカウント計6件に不正ログインされた。
- 不正アカウントは12日間気づかれなかった。2段階認証が必須になり、詳しい原因と影響範囲は調査中。

> この記事では、公式発表・報道で確認できた内容を「事実」、筆者の推測や意見を「考察」として分けて書いています。確認できなかった情報は書いていません。

## 発表内容の整理

**事実（ベーシック、10月27日14時30分時点）**

| 項目 | 内容 |
| --- | --- |
| 対象サービス | マーケティングプラットフォーム「ferret One」 |
| 原因 | 内部管理機能の不備。不正アクセスの経路の全容と原因は調査中 |
| 閲覧・取得の可能性がある情報 | 導入企業のログイン用メールアドレス（氏名などは含まない） |
| 不正ログイン | ベーシックと顧客のアカウント計6件。パスワードを初期化し、対象顧客に個別連絡 |
| 対応 | 不正アカウントの削除と不備の修正、2段階認証の必須化と該当アカウントのパスワード初期化、管理機能へのアクセス制限の強化 |
| サービス | 継続して利用可能 |

- 同社は、同社や関係先を装った不審なメールに注意し、ログインはブックマークから行い、他のサービスと同じパスワードを使っている場合は変更するよう呼びかけている。問い合わせは専用フォームとメール（houmu@basicinc.jp）で受け付ける（[ferret One](https://ferret-one.com/notice/20261027)）。
- 発表は調査の完了を待たずに出した第一報と位置づけられている（同）。

**考察**

漏れた可能性があるのはメールアドレスだけとされるが、不正ログインされた6件の中には顧客のアカウントが含まれる。ferret OneはWebサイトのCMSやフォーム、メール配信の機能を持つため、顧客アカウントに入られると、そのサイトに集まった問い合わせやリードの情報、サイトの内容そのものに手が届く可能性がある。6件で何が見られたかは、利用企業にとって最も気になる点だ（考察）。

「内部管理機能」でアカウントが作られたのが10月14日、気づいたのが26日で、12日間の空白がある。運営者向けの管理機能でのアカウント作成は本来まれな操作のはずで、作成の通知や監視がなかったのかは再発防止策で示されるべき点だろう（考察）。

## 関係しそうな既知の手口

**事実（既知の知見）**

- JPCERT/CCは10月8日に公開し、その後更新している注意喚起で、国内で相次ぐ不正アクセスの類型の一つとして、ユーザー権限の変更を含む、アプリの管理用APIへの不正なリクエストを挙げている（[JPCERT/CC](https://www.jpcert.or.jp/at/2026/at260030.html)）。
- 10月26日には、台東区の障害者支援アプリ「ささえ～る」でも、委託先の仕組みの不備から外部の第三者が管理者アカウントを作れてしまった事案が公表されている（[台東区](https://www.city.taito.lg.jp/kenkohukusi/shogai/osirase/0000000000.html)）。

**考察**

管理用のアカウントを外から作られる事案が国内で続いている。ferret Oneの不備がどの型かは公表されていないが、管理機能でのアカウント作成・権限付与を外部から受け付けてしまう欠陥は、JPCERT/CCの示した類型と同じ方向の問題とみられる。同社が「管理機能へのアクセス制限の強化」を挙げていることも、この見方と矛盾しない（考察）。

## 利用者・運用者がいまできること

- ferret Oneの導入企業は、ベーシックからの個別連絡の有無を確認し、2段階認証を設定する。同じパスワードを他のサービスでも使っていたら変える。
- 自社のferret Oneで、10月14日以降に覚えのないユーザー追加、ページやフォームの変更、データの書き出しがないかを確認する。
- ferret Oneを名乗るメールのリンクからログインしない。ログインはブックマークから行う。
- SaaSを提供する事業者は、運営者向けの管理機能が外部から届かないようにし、管理アカウントの作成や権限変更を即時に通知・記録する仕組みを持つ。
